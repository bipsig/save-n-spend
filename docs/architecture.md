## Repository layout

Save n Spend is a single npm-workspaces monorepo.

| Workspace | Package name | Contents |
|---|---|---|
| `apps/api` | `api` | Express 4 + Mongoose 8 REST service, compiled as CommonJS. |
| `apps/mobile` | `mobile` | Expo SDK 54 / React Native 0.81 iOS app using expo-router. |
| `packages/types` | `@save-n-spend/types` | Domain interfaces shared by both applications. |

`packages/types` is the contract between the two applications. When you change
a domain shape, change it there first — both sides compile against it, so a
mismatch becomes a type error instead of a runtime surprise.

**Important**
`apps/mobile/ios/` is generated by `expo prebuild` and is excluded from version
control. Never hand-edit it: the next prebuild discards your changes. Express
native configuration through `app.json` and config plugins instead.

## How a request flows

```
mobile screen
  → lib/<domain>.ts hook           (useBudgets, useGoals, …)
    → lib/api.ts                   (fetch wrapper; attaches the bearer token)
      → POST /api/v1/<resource>
        → routes/v1/<domain>Routes.ts
          → protect                (JWT verification)
            → controllers/<domain>Controller.ts
              → schemas/<domain>Schema.ts   (Zod validation)
                → models/<Model>.ts         (Mongoose)
                  → utils/response.ts       (envelope)
```

Every route is mounted under `/api/v1`. The router chain is
`server.ts` → `routes/router.ts` (`/v1`) → `routes/v1/index.ts` (per-resource
routers).

Controllers own validation and orchestration. They parse input with the Zod
schema for their resource, act on the model, and reply through a helper from
`utils/response.ts`. Business rules that span more than one document live in
`services/`.

## Money representation

**All monetary amounts are integer paise.** There are no floating-point rupee
values anywhere in the system: not in request bodies, not in Mongoose
documents, not in mobile state.

| Layer | Representation | Example for ₹1,234.50 |
|---|---|---|
| API request and response | integer paise | `123450` |
| MongoDB document | integer paise | `123450` |
| Mobile state and forms | integer paise | `123450` |
| Mobile display | formatted string | `₹1,234.50` |

Convert only at the edges of the mobile app, using `apps/mobile/lib/money.ts`:

| Function | Purpose |
|---|---|
| `formatMoney(paise)` (default export) | Paise to a display string with Indian digit grouping. |
| `parseMoney(text)` | User-entered rupee text to integer paise. |
| `paiseToInput(paise)` | Paise to the plain rupee string a text field expects. |

**Warning**
Never send a rupee float to the API. Every amount field is declared
`z.number().int()`, so a fractional value fails validation with a 400 — and a
value that happens to be integral is silently interpreted as paise, which is
off by a factor of 100.

## The account balance invariant

`Account.balance` is a cached running total. It is only ever modified by the two
functions in `apps/api/src/services/transactionService.ts`.

`getEffectOf(transaction)` maps a transaction to the balance deltas it implies.

| Transaction type | Effect |
|---|---|
| `expense`, `negativeAdjustment` | `account` decreases by `amount`. |
| `income`, `positiveAdjustment` | `account` increases by `amount`. |
| `transfer` | `account` decreases by `amount`; `toAccount` increases by `amount`. |

`applyEffects(transaction, action, session)` applies those deltas with `$inc`.
Pass `"add"` when a transaction comes into existence and `"revert"` when it
leaves. An update is a revert of the old document followed by an add of the new
one.

**Important**
Every call runs inside `session.withTransaction`, so the transaction document
and the balance move together or not at all. If you add a code path that
creates, edits, or deletes a transaction, route it through `applyEffects` inside
a session. Writing to `Account.balance` directly will drift the balance away
from the transaction history, and nothing in the system will detect it.

This is why MongoDB Atlas is a hard requirement rather than a preference:
multi-document transactions need a replica set.

## Response envelope

Every response — success or failure — has the same four fields.

```json
{
  "success": true,
  "statusCode": 200,
  "message": "Success",
  "data": { }
}
```

| Field | Type | Description |
|---|---|---|
| `success` | boolean | `true` for 2xx, `false` otherwise. |
| `statusCode` | number | Repeats the HTTP status, so a client that only reads the body still knows. |
| `message` | string | Human-readable. On failure this is the text the app shows the user. |
| `data` | any | The payload, or `null` on failure and for deletes. |

Emit the envelope with a helper from `apps/api/src/utils/response.ts` —
`ok`, `created`, `noContent`, `badRequest`, `unauthorized`, `forbidden`,
`notFound`, `conflict`, `serverError` — rather than calling `res.json`
yourself.

On the mobile side, `lib/api.ts` unwraps the envelope and returns `data`
directly, so callers never see the wrapper:

```ts
const budgets = await get<BudgetSummary[]>("/budgets?month=2026-07");
```

**Note**
`noContent` returns HTTP 200 with `data: null`, not HTTP 204. The name follows
the semantics, not the status code.

## Error handling

`apps/api` imports `express-async-errors`, so a rejected promise in an async
handler reaches the error middleware without an explicit `try`/`catch`. Throw
and let it propagate:

```ts
if (!budget) throw AppError.notFound("Budget not found");
```

`AppError` (in `utils/AppError.ts`) carries an HTTP status alongside the
message, with static constructors for the common cases: `badRequest`,
`unauthorized`, `forbidden`, `notFound`, `conflict`.

`middleware/errorHandler.ts` is the single exit point. It maps each error class
to a status and an envelope:

| Error | Status | Message the client sees |
|---|---|---|
| `AppError` | `err.statusCode` | `err.message` |
| `ZodError` | 400 | The first issue's message. |
| `mongoose.Error.CastError` | 400 | `Invalid <path>: <value>` |
| `mongoose.Error.ValidationError` | 400 | All field messages, comma-joined. |
| MongoDB duplicate key (`11000`) | 409 | `A record with this value already exists` |
| Anything else | 500 | `Something went wrong. Please try again.` |

**Important**
The 500 branch logs the real error server-side and returns a generic message.
Keep it that way — internal details must not reach the client.

## Authentication

Registration and login return a JWT that is valid for 7 days. Every other route
is wrapped in `protect` (`middleware/authMiddleware.ts`), which expects:

```
Authorization: Bearer <token>
```

`protect` verifies the token with `JWT_SECRET` and attaches the payload to
`req.user`. A missing token yields `401 Token is missing`; an invalid or expired
one yields `401 Invalid or expired token`.

`POST /auth/register` and `POST /auth/login` are additionally rate-limited by
`middleware/rateLimiter.ts`. The API sets `trust proxy 1` so the limiter keys
off the real client IP rather than the hosting proxy's.

On the client, the token lives in `store/session.ts`, persisted with
expo-secure-store and hydrated synchronously on boot. `lib/api.ts` reads it per
request, and signs the user out automatically on any 401 outside `/auth/*` —
which is what returns them to the login screen.

## Period windowing

Screens that show a time window use a signed integer offset, not a date range.

| Offset | Meaning |
|---|---|
| `0` | The current period. |
| `-1` | The previous period. |
| `-n` | `n` periods back. |
| Positive | Not allowed. |

The API enforces this: `insightsQuerySchema` declares
`offset: z.coerce.number().int().max(0).default(0)`. The client enforces the
matching rule in the UI by disabling forward navigation at `offset === 0`
(`canNext={offset < 0}`).

All period math is done in **UTC** on both sides. `apps/api/src/utils/monthRange.ts`
builds `{ start, next, label }` from a `YYYY-MM` key using `Date.UTC`, and
`apps/mobile/lib/budgets.ts` derives its month keys the same way. Mixing local
and UTC time here shifts a day across a month boundary and silently
misattributes spend.

See [Add a period selector](mobile-patterns.md#add-a-period-selector) for the
client-side pattern.

## Configuration reference

### API environment variables

Set these in `apps/api/.env`.

| Variable | Required | Description |
|---|---|---|
| `PORT` | No | Listening port. Defaults to `3000`. Local development uses `7019`. |
| `DB_USERNAME` | Yes | Atlas cluster user. |
| `DB_PASSWORD` | Yes | Atlas cluster password. |
| `JWT_SECRET` | Yes | Signing secret. `protect` throws at request time if it is unset. |
| `SALT_ROUNDS` | No | bcrypt cost factor. `10` locally. |
| `NODE_ENV` | No | `production` selects the production database. Anything else selects dev. |
| `DB_NAME` | No | Overrides the resolved database name — for a throwaway test database. |

There is no `MONGO_URI`. `config/db.ts` assembles the connection string from
`DB_USERNAME` and `DB_PASSWORD` against a fixed cluster host, then selects the
database with mongoose's `dbName` option:

| `NODE_ENV` | Database |
|---|---|
| `production` | `save-n-spend-prod` |
| anything else | `save-n-spend-dev` |

**Important**
The database is chosen by `NODE_ENV`, not by a separate connection string, and
both databases live on the same cluster. Setting `NODE_ENV=production` in a local
`.env` therefore points your development machine at production data. Leave it
`development` unless you mean it.

### Mobile environment variables

Only `EXPO_PUBLIC_*` variables are visible to app code.

| Variable | Description |
|---|---|
| `EXPO_PUBLIC_API_URL` | Full API base, including `/api/v1`. When unset, `lib/api.ts` derives the Metro host and appends `:7019/api/v1`. |

`apps/mobile/.env.production` is committed deliberately. Expo inlines
`EXPO_PUBLIC_*` into the JavaScript bundle at build time, so these values are
readable by anyone with the binary and must never hold a secret.

**Important**
Because the value is inlined at build time, editing `.env.production` has no
effect until you rebuild. The `npm run ipa` script prints the baked API URL at
the end of a build so you can confirm what the binary will actually call.
